# Project conventions

These rules win over any plugin or style guide (Ponytail, Caveman, …). "Less code" or "be brief" never means skipping `t()`, the form's zod schema, `ActionResult`, `runAction`, a permission check, a test for a new action, or the folder layout below.

**UI follows `DESIGN.md`** (look and feel: colour, type, components, layout, touch, navigation, motion) — read it before building or changing any screen.

- **UI**: use shadcn/ui for everything it covers (`pnpm dlx shadcn@latest add <name>`). Preset `b3S8pyK7k` (`base-mira`, neutral base, solid menus; applied with `shadcn apply --only theme` to keep Cairo), Base UI, RTL on.
- **shadcn files stay as generated.** Any edit to a generated file (even one class) gets a comment right above it starting with `// Updated:` describing the change.
- **Icons**: Hugeicons only, imported from `@/components/icons` — never from `@hugeicons/*` directly. Its `HugeiconsIcon` sets the stroke (`ICON_STROKE`); never pass `strokeWidth` per icon. Add new icons to that file. After `shadcn add`, repoint the component's icon imports there (with an `// Updated:` comment).
- **i18n**: `src/lib/i18n` — `getTranslations()` on the server, `useLocale()` on the client. Keys are the English text; add translations to `messages/ar.ts` (English and Arabic only). Use logical classes (`ms-`, `pe-`, `start-`, `text-start`) so RTL works.
- **DB**: Drizzle + postgres-js. Import `db` from `@/db` (server only). One schema file per domain in `src/db/schema/`, re-exported from its `index.ts`; spread `...id, ...timestamps` from `@/db/helpers`; name columns by key only (snake_case is automatic). Change schema → `pnpm db:generate` → `pnpm db:migrate`. Validate outside ids with `isValidId` (`@/db/helpers`). Any standard Postgres host (no vendor features). **Every write is an action**: `runAction({ action, actorId, source, input, note }, (tx) => …)` (`server/run-action.ts`) records who did what and why in `history` and runs the writes in one transaction; the `history` trigger (on every table except sign-in internals, `post_votes`, `post_saves`) records each row's before → after under that action. Never `db.insert/update/delete` outside it — `e2e/rules.spec.ts` fails (allowed: votes/saves, rate limits). A new table gets the trigger with `select history_attach('<table>')` in its migration (the rules spec checks). History never stores emails or secrets. Names people type are `{ en, ar }` (`Localized`, at least one, database `has_text` check), shown with `inLocale()` (falls back to the other language); people's names and free text are plain text. Statuses are database enums, changed only by actions. People are never deleted, only anonymized (`anonymizeUser`, `server/anonymize.ts`); a business is soft-deleted (status `deleted`). The database refuses putting a place inside itself. What the public sees is one helper per table (`visible` in `server/queries/posts.ts`, `publicReviews`, `listed`) — counts and ratings use it too.
- **Env**: read variables only via `env` from `@/lib/env` (zod-validated at startup) — never `process.env` directly. New variable → add it to the schema there and to `.env.example`.
- **Where code lives**: `src/server/actions/` holds every server action (`"use server"`; only `lib/i18n/actions.ts` and `lib/auth` stay with their libraries); `src/server/queries/` every database read; the rest of `src/server/` is server-only code that writes or decides who's acting (`run-action.ts`, `actor.ts`, `tickets.ts`, `status-writes.ts`, `anonymize.ts`, `rate-limit.ts`). `src/lib/` is library setup and client-safe helpers — no database writes.
- **Forms & actions**: every server action returns `ActionResult` (`lib/action-result.ts`: `ok(data)` / `done()` / `fail(key, field?)`, `invalid(zodError)` for a schema's first problem, `AGAIN`, `NOT_ALLOWED`) — user errors are values, never throws; `field` puts the error under that form field, otherwise it's a toast. An action: check who's acting (fresh session, rate limit), validate with the form's shared zod schema, write (`runAction`), return `ActionResult`. Schemas: one file per form in `lib/validations/` named like the form (`business-form.ts`), shared rules in `lib/validations/utils.ts`; messages are message keys. Forms: all in `components/forms/` (one file per form, kebab-case, named `…-form.tsx`), one file per shared field (`text-field.tsx`, `textarea-field.tsx`, `localized-field.tsx`, `username-field.tsx`; `FormError`/`INPUT` in `form-error.tsx`). Submit with `useActionForm` (`hooks/use-action-form.ts`: schema, defaults, action, `onDone`, success toast) — never a hand-written `handleSubmit`. One-tap actions without a form (delete, follow, vote, save, report, cancel) run through `useAction` (`hooks/use-action.ts`): `run(() => action(...), { success, onDone, onError, refresh })` — error toast, offline message, optimistic undo in `onError`, `refresh: false` for optimistic UI; never check `result.ok` and toast by hand. A form never owns its sheet or dialog: it takes `onDone` (and `onCancel`).
- **Auth**: Better Auth, Google only (`src/lib/auth`). Server: `getSession()` / `requireUser()` to render and guard pages (cookie-cached, no DB query), `getFreshSession()` before every write. The proxy only does cookie-presence redirects; never trust it for authorization. People (`users`) follow and review businesses and post, optionally as one of their businesses; there is no `profiles` table.
- **Mobile**: the phone feel (44px taps, safe areas, keyboard, sheets, skeletons, pull to refresh) is `DESIGN.md` §4–6 — follow it on every screen.
- **Places**: a tree in the `places` table (no depth limit; `place_types` for city/markaz/village…). Posts and branches store a `placeId` and show in it and every place above it — filter with `inPlaceTree(column, slug)` (`server/queries/places.ts`, one recursive query), never a hand-written list. Server: `getPlaceIndex()` (cached whole, tag `PLACES_TAG` — call `updateTag(PLACES_TAG)` after any place write) and `getCurrentPlace()` (the visitor's pick, cookie). Client: `usePlaces()` (every place, from the root layout). Pick a place with `<PlaceField>` / `<PlacePicker>` (`components/places`), a drill-down sheet. People ask for new places with `new_place` tickets; places themselves are only added in the database (seed / migrations). There are no admins: nobody answers tickets in the app.
- **Requests & reports**: there are no admin roles, admin screens or moderation. **Requests and reports are tickets** (one `tickets` table): each type is defined once in `lib/tickets/types.ts` (who may send it, what it's about — `refs` to any records — its zod `data`, its statuses) and handled by `server/tickets.ts` — `openTicket` (checks refs, one open ticket per sender and subject via `openKey`) and `cancelTicket` (the sender takes it back). Read them with `server/queries/tickets.ts`. Tickets are only recorded: reports never hide anything. Statuses other than the ones people set themselves (`hidden` posts and reviews, `pending` / `suspended` businesses, `suspended` users) are only set in the database. Who runs a business (edits it, posts as it, changes its status): its owner, or whoever added it **only while it has no owner** — use `roleFor` / `canManage` (`lib/business-status.ts`), never compare `createdById` by hand. A business's old @handle isn't kept: once it changes, it's free for any business (old links show "not found").
- **One app**: `app/(app)/` is the phone app; `(auth)` (sign-in) is shared.
- **Navigation**: `DESIGN.md` §7 (`<Screen>`, `<AppHeader>`, `<StackLink>`, never `router.push()`, back and edge swipe).
- **Phone integration**: `DESIGN.md` §8 (`useShare()`, brand images, `<ThemeColor>`).
- **Offline**: `public/sw.js` (production only; dev unregisters it) — pages network-first and saved as visited, `/offline` fallback for unvisited ones, `/_next/static` cache-first, `/api` and RSC requests never cached. Bump `VERSION` in it when the caching logic changes (drops old caches). Anything showing private data must be cleared on sign-out (`clearSavedPages()`). Offline tests only run against a build.
- **SEO**: pages set only their own `title` (the root template adds "· Qura"). Public pages add `alternates: { canonical: href(...) }` and go in `app/sitemap.ts`; personal/auth pages set `robots: { index: false }` (don't block them in robots.txt — crawlers must see the noindex). Never set canonical/og:url in a layout (every child inherits it).
- **Tests**: `pnpm test` (Vitest, `src/test/*.test.ts`): the real server actions and queries against `qura_test` on the local Postgres (`docker compose up -d`), rebuilt from the migrations every run; sign in with `signIn(person)` and build records with the helpers in `src/test/helpers.ts` (`person`, `business`, `post`, `data`, `refused`). Every action gets a test there (what it allows, what it refuses, what it writes); never point tests at the `.env` database. `pnpm e2e` (Playwright, phone-sized; `signIn()` signs in as the test user, starts/reuses `pnpm dev`; Edge on Windows). Any console/page error fails a test. Add an e2e spec for each screen or gesture; use the helpers in `e2e/fixtures.ts` (`waitForHydration` before tapping, `recordTransitions`/`transitionOf` for animations). Against production: `E2E_BASE_URL=http://localhost:3100 pnpm e2e` — the reference run; transition checks can flake in dev (on-demand compiling splits navigations). Never run `pnpm build` while `pnpm dev` is running (shared `.next` → corrupted dev cache).
