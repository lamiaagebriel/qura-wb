# Project conventions

- **UI**: use shadcn/ui for everything it covers (`pnpm dlx shadcn@latest add <name>`). Preset `b1x9M8ZeJW` (`base-mira`, taupe base, dark primary; applied with `shadcn apply --only theme` to keep Cairo), Base UI, RTL on.
- **shadcn files stay as generated.** Any edit to a generated file (even one class) gets a comment right above it starting with `// Updated:` describing the change.
- **Icons**: Hugeicons only, imported from `@/components/icons` — never from `@hugeicons/*` directly. Add new icons to that file. After `shadcn add`, repoint the component's icon imports there (with an `// Updated:` comment).
- **i18n**: `src/lib/i18n` — `getTranslations()` on the server, `useLocale()` on the client. Keys are the English text; add translations to `messages/ar.ts` (English and Arabic only). Use logical classes (`ms-`, `pe-`, `start-`, `text-start`) so RTL works.
- **Font**: Cairo for all locales.
- **DB**: Drizzle + postgres-js. Import `db` from `@/db` (server only). One schema file per domain in `src/db/schema/`, re-exported from its `index.ts`; spread `...id, ...timestamps` from `@/db/helpers`; name columns by key only (snake_case is automatic). Change schema → `pnpm db:generate` → `pnpm db:migrate`. Validate outside ids with `isValidId` (`@/db/helpers`). Any standard Postgres host (no vendor features). **Every write is an action**: `runAction({ action, actorId, source, input, note }, (tx) => …)` (`lib/actions/run.ts`) records who did what and why in `history` and runs the writes in one transaction; the `history` trigger (on every table except sign-in internals, `post_votes`, `post_saves`) records each row's before → after under that action. Never `db.insert/update/delete` outside it — `e2e/rules.spec.ts` fails (allowed: votes/saves, rate limits). A new table gets the trigger with `select history_attach('<table>')` in its migration (the rules spec checks). History never stores emails or secrets. Names people type are `{ en, ar }` (`Localized`, at least one, database `has_text` check), shown with `inLocale()` (falls back to the other language); people's names and free text are plain text. Statuses are database enums, changed only by actions. People are never deleted, only anonymized (`anonymizeUser`, `lib/users/anonymize.ts`); a business is soft-deleted (status `deleted`). The database refuses removing the last active super admin and putting a place inside itself. What the public sees is one helper per table (`visible` in `lib/data/posts.ts`, `publicReviews`, `listed`) — counts and ratings use it too.
- **Env**: read variables only via `env` from `@/lib/env` (zod-validated at startup) — never `process.env` directly. New variable → add it to the schema there and to `.env.example`.
- **Auth**: Better Auth, Google only (`src/lib/auth`). Server: `getSession()` / `requireUser()` to render and guard pages (cookie-cached, no DB query), `getFreshSession()` before every write, `requireAdmin()` (fresh) for admin. The proxy only does cookie-presence redirects; never trust it for authorization. People (`users`) follow and review businesses and post, optionally as one of their businesses; there is no `profiles` table.
- **Mobile (native feel)**: tap targets ≥ 44px (`size-11` / `h-11`, `size="xl"` buttons); touch behavior lives in `globals.css` (no tap highlight, no double-tap zoom, no page rubber-band, pressed state on touch, 16px inputs) — don't override it per component. Heights and safe areas only via the iOS-corrected vars in `globals.css`: `min-h-(--app-height)`, `pt-[var(--safe-top)]`, `pb-[var(--safe-bottom)]` — never `vh`/`dvh`/raw `env(safe-area-inset-*)`. Keyboard: `<KeyboardObserver>` (`components/keyboard.tsx`) sets `html[data-keyboard=open]` (tab bar hides) and `--keyboard-inset` — a bar that must sit on the keyboard uses `bottom: var(--keyboard-inset)`; dragging or tapping empty space dismisses it (opt out: `data-keep-keyboard`). Give text fields the right `enterKeyHint`/`inputMode`/`autoComplete`, and blur on submit. Refreshable screens wrap their content under `<AppHeader>` in `<PullToRefresh>` (`components/pull-to-refresh.tsx`; `router.refresh()` by default, or `onRefresh` for client data). Bottom sheets use the vaul `Drawer` (controlled — back closes it first, built in). Options → `ActionSheet`, confirmations → `ConfirmSheet` (`components/sheets`), never menus/popovers or `confirm()`. Every screen gets a `loading.tsx` skeleton matching its layout (`components/skeletons.tsx`: `Bone`, `SkeletonBody`, `PostSkeleton`, `ListCardSkeleton`), wrapped in `<Screen>` with the same `<AppHeader>`.
- **Places**: a tree in the `places` table (no depth limit; `place_types` for city/markaz/village…). Posts and branches store a `placeId` and show in it and every place above it — filter with `inPlaceTree(column, slug)` (`lib/data/places.ts`, one recursive query), never a hand-written list. Server: `getPlaceIndex()` (cached whole, tag `PLACES_TAG` — call `updateTag(PLACES_TAG)` after any place write) and `getCurrentPlace()` (the visitor's pick, cookie). Client: `usePlaces()` (every place, from the root layout). Pick a place with `<PlaceField>` / `<PlacePicker>` (`components/places`), a drill-down sheet. New places come from `new_place` tickets answered by the super admin or an admin of the parent; only the super admin creates top-level places and adds/removes place admins (place admins only *request* it).
- **Roles & moderation**: super admin = `users.role`; place admins = `place_admins` rows, each for **one** place (never the places inside it). Check with `isPlaceAdmin()` / `adminPlaceIds()` (`lib/data/place-admins.ts`) in every action. The phone app has no place-admin screens (members only request places and cancel their requests, `/profile/places`); places and moderation are answered in the dashboard. **Requests and reports are tickets** (one `tickets` table): each type is defined once in `lib/tickets/types.ts` (who may send it, what it's about — `refs` to any records — its zod `data`, its statuses) and handled by `lib/tickets/server.ts` — `openTicket` (checks refs, one open ticket per sender and subject via `openKey`), `decisionsFor` (who may answer what) and `answerTicket` (applies the outcome; the answer and its reason are history). Read them with `lib/data/tickets.ts`. Reports never hide anything by themselves: an admin decides (the inbox lists the most-reported first). A post's `status` is `visible` / `hidden` (reason only its author sees, from history) / `under_review` (the author edited it; an admin shows it again or keeps it hidden). Reviews are `visible` / `hidden`. Business reports: place admins dismiss or send them on (`escalated`); only the super admin suspends. Who runs a business (edits it, posts as it, changes its status): its owner, or whoever added it **only while it has no owner** — use `roleFor` / `canManage` (`lib/business-status.ts`), never compare `createdById` by hand. A business's old @handle isn't kept: once it changes, it's free for any business (old links show "not found").
- **Two apps, one root layout**: `app/(app)/` is the phone app (everything above about Screen/AppHeader/StackLink/sheets applies there); `app/(admin)/admin/` is the super admin dashboard, desktop-first and still usable on a phone. `(auth)` (sign-in) is shared. Every database table is a **resource** (`lib/admin/resources/*.ts`, registered in `lib/admin/registry.ts`, listed in `lib/admin/menu.ts`): its columns, filters, search and list query (all server-side, state in the URL), its record page (`/admin/<table>/<id>`: editable fields, locked fields with a reason, actions, related rows, delete rules) and its writes. Cells are plain data (`lib/admin/types.ts`) rendered by `DataTable` / `CellView` — never show an id: a reference is the linked name (`recordHref`). Editable fields are a zod schema in `lib/admin/schemas.ts`, used by the form and re-checked by `saveRecord`; every save, action and delete goes through `components/admin/record-actions.ts`, which runs it as an action (`source: "dashboard"`, writes through `ctx.tx`; a resource whose `act` records its own action — answering tickets, hiding — sets `actsOnItsOwn`). The inbox (`/admin/requests`, `/admin/reports`) is `components/admin/ticket-inbox.tsx`; `/admin/tickets` lists every ticket and `/admin/history` every action and change (`?actionId=` one action's changes, `?table=&record=` one record's). Statuses only change through actions; hard delete only where a resource sets `deletion` (typed confirmation). Wrap screens in `<AdminPage>`, call `requireAdmin()` in every page, menus and `AlertDialog`s are fine here (unlike the phone app). Plain `<Link>` between dashboard screens. Admin server actions re-check `role === "super_admin"` with a fresh session. Later: the dashboard moves to a subdomain.
- **Navigation**: wrap every page in `<Screen>`; use `<AppHeader>` (`large` on tab roots, `back={href("parent")}` on detail screens, max one `action`); open deeper screens with `<StackLink>` (slides in), never plain `<Link>`; tabs are defined in `lib/navigation.ts`. Forward navigation is always a real `<Link prefetch transitionTypes={[navType(...)]}>` (StackLink does this) — never `router.push()`/`addTransitionType`: on dynamic screens the router then commits twice and the slide animates the wrong page. Tabs are plain links to their root. The back arrow (`BackButton`) is `router.back()` when an in-app screen is behind it (instant, like browser back); on a deep link it replaces the screen with the `back` parent, sliding back, so back never leaves the app (`navigation/history.tsx` counts in-app screens). In the installed app, an edge swipe goes back on any screen with a back arrow (`use-swipe-back.ts`) — don't add horizontal-swipe gestures at the screen edges.
- **Phone integration**: share with `useShare()` (`lib/share.ts`, native sheet → copy-link + toast), never `alert()`. Brand colors/sizes in `lib/brand.ts` (safe anywhere); icons & iOS splash screens are drawn in `lib/brand-images.tsx` (server-only) — replace the placeholder mark there. `theme-color` is managed by `<ThemeColor>`; don't set it per page.
- **Offline**: `public/sw.js` (production only; dev unregisters it) — pages network-first and saved as visited, `/offline` fallback for unvisited ones, `/_next/static` cache-first, `/api` and RSC requests never cached. Bump `VERSION` in it when the caching logic changes (drops old caches). Anything showing private data must be cleared on sign-out (`clearSavedPages()`). Offline tests only run against a build.
- **SEO**: pages set only their own `title` (the root template adds "· Qura"). Public pages add `alternates: { canonical: href(...) }` and go in `app/sitemap.ts`; personal/auth pages set `robots: { index: false }` (don't block them in robots.txt — crawlers must see the noindex). Never set canonical/og:url in a layout (every child inherits it).
- **Tests**: `pnpm e2e` (Playwright, phone-sized — dashboard specs set a desktop viewport; `signIn("admin")` signs in as the test super admin, starts/reuses `pnpm dev`; Edge on Windows). Any console/page error fails a test. Add a spec in `e2e/` with each feature; use the helpers in `e2e/fixtures.ts` (`waitForHydration` before tapping, `recordTransitions`/`transitionOf` for animations). Against production: `E2E_BASE_URL=http://localhost:3100 pnpm e2e` — the reference run; transition checks can flake in dev (on-demand compiling splits navigations). Never run `pnpm build` while `pnpm dev` is running (shared `.next` → corrupted dev cache).
